KAIRO V1 - PERSONAL DEVICE TEST RUNBOOK
========================================

Last updated: 2026-08-14
Project: /home/student/Kairo-v1
Mobile app: /home/student/Kairo-v1/apps/mobile

Purpose
-------

This runbook tests the current Kairo mobile app on a real physical device before Phase 2
sync and authentication work begins.

The current implementation includes:

- Workouts
- Weight and progress charts
- Daily tasks and streaks
- Macro and nutrition tracking
- A Home dashboard aggregating all four modules

The current automated baseline is:

- TypeScript typecheck: clean
- ESLint: clean
- Jest: 319 tests passed across 12 suites
- Expo Doctor: 20/20 checks passed
- Android production export: successful

The physical test is for native behavior, persistence, navigation, layout, keyboard use,
SQLite migration behavior, force-close recovery, and touch ergonomics. It is not a web test.


1. IMPORTANT TESTING RULES
--------------------------

1. Test the existing database before clearing application data. This verifies the v4 SQLite
   migration preserves workouts, weights, tasks, and completions from earlier versions.

2. Do not use development-client mode. The project does not install expo-dev-client.

3. Do not open the web target during this test. The app is being tested on Android or iOS.

4. Do not press the Expo CLI `w` key. That starts a browser bundle and can produce a
   wa-sqlite.wasm Metro error that is unrelated to native Android/iOS testing.

5. Do not use `--localhost` for a physical phone. A phone cannot reach the computer's
   localhost address.

6. Do not clear Expo Go storage until the optional fresh-database test at the very end.
   Clearing it can remove the local database used by this project.

7. Keep the Metro terminal visible while testing. Native runtime errors and redbox messages
   often provide the most useful failure details there.


2. DEVICE AND COMPUTER PREPARATION
----------------------------------

Computer prerequisites:

- Node.js and npm installed
- Repository available at /home/student/Kairo-v1
- A physical Android or iOS device
- Expo Go installed on the device
- Computer and phone on the same Wi-Fi network for LAN mode

Before starting:

1. Disable a VPN on the computer and phone if one is active.

2. Do not use a guest Wi-Fi network that blocks device-to-device traffic.

3. Keep the phone awake and unlocked during the first launch.

4. On iOS, allow Expo Go to access the Local Network when prompted.

5. On Android, allow Expo Go to use the network if Android requests permission.

6. Record the test device and OS version. Example:

   OS: Android 15
   Expo Go: current App Store/Play Store version

7. Record the starting commit before making any additional changes:

   git rev-parse --short HEAD

5. START THE CORRECT NATIVE DEVELOPMENT SERVER
-----------------------------------------------

Use Expo Go explicitly and force LAN mode:

   cd /home/student/Kairo-v1/apps/mobile
   npx expo start --go --lan -c

Meaning of the flags:

- `--go` forces Expo Go mode.
- `--lan` advertises the computer on the local network.
- `-c` clears the Metro JavaScript cache.

Wait for output similar to:

   Using Expo Go
   Scan the QR code above with Expo Go

On Android:

1. Open Expo Go.
2. Use Expo Go's QR scanner.
3. Scan the QR code in the Metro terminal.

On iOS:

1. Open the normal Camera app.
2. Scan the QR code.
3. Open the link in Expo Go.

Do not scan a QR code that says it is for a development build. If the terminal says
"Using development build", stop it with Ctrl+C and restart with:

   npx expo start --go --lan -c

If LAN cannot connect, use tunnel mode:

   npx expo start --go --tunnel -c

Tunnel mode may be slower and may require network access to download or start the tunnel.

7. EXISTING-DATA AND MIGRATION TEST
-----------------------------------

Perform this before clearing Expo Go data or reinstalling Expo Go.

1. Open Workouts and confirm old workout history is still present.

2. Open Weight and confirm old weigh-ins and the goal, if previously configured, remain.

3. Open Today and confirm old tasks, completion states, and streak history remain.

4. Open Macros. The first launch after the new build should create migration v4 without
   removing any existing data.

7. Reopen the project from Expo Go's recent projects list.

8. Verify all four existing modules still show their data.

Pass condition: the app upgrades to v4 and all v1-v3 data survives.

If the device has never run an earlier Kairo version, this manual migration scenario cannot
be reproduced there. The automated SQLite migration suite covers the populated v3-to-v4 path.

19. COMMON ISSUES AND FIXES
---------------------------

Issue: The terminal says "Using development build".

Fix: Stop Metro with Ctrl+C and run:

   npx expo start --go --lan -c

Do not install expo-dev-client for this test.

Issue: A browser opens or Metro reports `wa-sqlite.wasm` missing.

Fix: Close the browser. Do not press `w`. Restart with the native Expo Go command:

   npx expo start --go --lan -c

The web target is not part of this physical-device test. The WASM file is present for the
package, but browser Metro resolution is a separate configuration concern.

Issue: The QR code cannot be reached over LAN.

Fixes:

1. Confirm computer and phone are on the same non-guest Wi-Fi.
2. Disable VPNs.
3. Allow the terminal through the computer firewall.
4. Try tunnel mode:

   npx expo start --go --tunnel -c

Issue: The QR code opens but the app cannot load JavaScript.

Fixes:

1. Confirm the computer is still running Metro.
2. Confirm the phone is not on cellular data only.
3. Restart with `npx expo start --go --lan -c`.
4. Try tunnel mode.
5. Record the exact Expo Go error and Metro terminal output.

Issue: Expo Go reports that the project is incompatible.

Fixes:

1. Update Expo Go from the App Store or Play Store.
2. Confirm the project is using Expo SDK 57 dependencies.
3. Run `npm install` from `apps/mobile`.
4. Run `npx expo-doctor`.
5. Do not randomly upgrade Expo packages during this test.

Issue: Metro says port 8081 is already in use.

Fix: Stop the other Metro process, or use another port:

   npx expo start --go --lan --port 8082 -c

Issue: The app shows a blank screen after a code update.

Fixes:

1. Stop Metro.
2. Restart with `npx expo start --go --lan -c`.
3. Reload the project in Expo Go.
4. Check the Metro terminal for the first error, not only the final redbox message.

Issue: A migration error appears on startup.

Fixes:

1. Do not clear data immediately.
2. Capture the exact SQLite error and current app state.
3. Confirm whether the device had an older Kairo database.
4. Compare against the automated migration test result.
5. Only clear data after the existing-data evidence has been captured.

Issue: Existing data appears to be missing.

Fixes:

1. Confirm you did not clear Expo Go storage.
2. Confirm you opened the same Kairo project and not a stale QR URL.
3. Fully close and reopen Expo Go.
4. Check the Metro terminal for database initialization errors.
5. Do not create replacement data until the issue is understood.

Issue: The Home card is stale after returning from another module.

Fixes:

1. Navigate away from Home and return through the tab bar.
2. Wait for the loading state to finish.
3. Check whether the module write itself succeeded.
4. Capture the sequence and data values if Home still disagrees with the module screen.

Issue: Keyboard covers a form button.

Fixes:

1. Scroll the form while the keyboard is open.
2. Test both decimal and numeric keyboard layouts.
3. Record the device model, OS, orientation, and field where it occurs.

Issue: Long press does nothing.

Fixes:

1. Press and hold the row rather than the text only.
2. Try a longer hold, approximately one second.
3. Confirm the row is a persisted entry and not an empty section.

Issue: Expo Go closes or shows a native crash.

Fixes:

1. Capture device logs if available.
2. Record the exact action immediately before the crash.
3. Check whether the crash occurs only after force-closing or only on one device.
4. Do not assume a JavaScript test pass rules out a native issue.


20. FAILURE REPORT FORMAT
-------------------------

For every failure, record:

- Device model
- OS version
- Expo Go version
- Kairo commit SHA
- Exact test section and step number
- Expected result
- Actual result
- Whether the issue reproduces after reload
- Whether the issue reproduces after force-close and reopen
- Screenshot or screen recording
- Full Metro terminal error
- Native device log, if available

Avoid reporting only "it does not work". The exact action and first terminal error are needed
to diagnose the issue efficiently.

The device test is complete when all of these are true:
